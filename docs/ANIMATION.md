# 애니메이션 — 어떻게 만들어지는가

이 게임의 캐릭터 동작에는 **모션 캡처 데이터가 한 프레임도 들어 있지 않습니다.**
관절 각도를 수식과 표로 적어서 Blender로 굽고, 나머지 절반은 게임이 도는 동안
만듭니다. 이 문서는 그 경로 전체와, 무엇을 어디서 고치는지를 적습니다.

일어난 일의 **경위**(왜 이렇게 됐는지, 무엇을 틀렸다 고쳤는지)는 `README.md`에
있습니다. 여기는 **지금 상태**와 **바꾸는 법**입니다.

### 텍스처를 직접 칠할 때의 함정

`assets/characters/*_texture.png` 는 **Godot 이 GLB 에서 뽑아낸 것**입니다
(`gltf/embedded_image_handling=1`). 그림은 GLB 안에 들어 있고, 옆의 png 는
그 사본입니다.

- **칠하면 곧바로 게임에 반영됩니다.** 재질이 이 png 를 봅니다.
- **다시 구우면 지워집니다.** GLB 를 새로 만들면 png 도 다시 뽑히기 때문입니다.

그래서 빠르게 보고 고칠 때는 png 를 직접 칠하고, **남길 것은 blend 로
돌려놓아야** 합니다.

### 굽고 나면 규격을 확인합니다

새로 구운 캐릭터의 텍스처가 폰 규격에서 빠지기 쉽습니다(실제로 물물교환 아이
하나가 2048 무압축으로 남아 VRAM 을 16MB 먹고 있었습니다).

```bash
grep -h "size_limit\|compress/mode" assets/characters/*_texture.png.import | sort | uniq -c
```

같은 줄이 여덟 벌 나와야 맞습니다.

        ▼
Blender 로 키프레임 굽기     walk_worker.py → art_src/src/<이름>_<동작>.glb
        │
        ▼
합치기 + 골반 보정           merge_anims.graft → raise_hips.py → assets/characters/<이름>.glb
        │
        ▼
Godot 런타임                 ① 클립 재생 속도를 이동 속도에 맞춤
                             ② 자세 층(PoseOverride)이 특정 본만 덮어씀
                             ③ jiggle / ragdoll
```

앞의 넷은 `python tools/make_kids.py --force` 한 줄로 다시 돕니다(Blender 필요).
마지막 하나는 GDScript라 다시 굽지 않아도 됩니다.

## 믹사모와의 관계

믹사모는 웹 서비스이고 **공개 API가 없어 자동화할 수 없습니다**(Adobe 로그인 →
브라우저 업로드 → 리그 마커 찍기). 그래서 절차적으로 만드는 길을 택했습니다.

다만 **본 이름은 믹사모 규약**(`Hips` / `Spine` / `LeftUpLeg` / `LeftForeArm` …)
으로 맞춰 두었습니다. 나중에 믹사모에서 받은 클립을 이 리그에 얹는 리타게팅이
이름만으로 대부분 붙습니다. 두 길은 배타적이지 않습니다.

| | 믹사모 | 여기 |
|---|---|---|
| 출처 | 배우 모션 캡처 | 애니메이션 교본의 관습 각도를 손으로 적음 |
| 데이터 크기 | 본 수십 개 × 프레임 수백 | 본 15개 × **키 5개** |
| 얻는 법 | 브라우저 조작, 자동화 불가 | `make_kids.py`, 몇 초 |
| 캐릭터 비례 | 리타게팅 필요 | **각도**라 그대로 |
| 고치기 | 편집기에서 커브를 만짐 | 숫자 하나 |
| 자연스러움 | 체중 이동·발 접지·비대칭이 다 들어 있음 | **없음**. 대칭적이고 기계적 |

이 프로젝트에서 실제로 필요했던 수정은 전부 뒤쪽 종류였습니다 — 무릎 부호,
보폭 재조정, 골반 높이, 뒷걸음 보폭. 그래서 이 방식이 맞습니다.

## 각도 규약 — 모든 층이 같은 규약을 씁니다

동작 데이터, `PoseOverride`, 리그 실험실이 **전부 같습니다.** 한 곳에서 익힌
감각이 다른 곳에 그대로 통합니다.

- 본의 **로컬 오일러 각(도), XYZ 순서**
- **로컬 X 양수 = 앞** (다리 스윙, 무릎, 팔 스윙)
- 로컬 Y = 본 축 둘레로 비틀기
- 로컬 Z = 좌우로 벌리기 — **좌우가 거울이라 부호가 반대**

로컬 축을 쓰는 이유: 파이프라인이 Y-up/Z-up 중 무엇으로 정렬했는지에 따라 월드
축이 달라집니다. 본은 항상 자기 Y축을 따라 뻗어 있으므로 "무릎을 굽힌다 = 로컬
X 회전"이 규약과 무관하게 성립합니다.

> **부호는 추측하지 말고 재세요.** 리그마다 축이 달라서 이 프로젝트에서 두 번
> 틀렸습니다(팔 앞뒤, 무릎 방향). 손·발 본에 `BoneAttachment3D`를 붙여 실제
> 위치를 찍어 보고 고릅니다. `Skeleton3D.get_bone_global_pose`는 자세 층이
> 반영되기 **전** 값이라 후보가 전부 같은 수를 냅니다 — 앵커를 쓰세요.

## 층 1 — 동작 데이터는 각도 표입니다

한 동작의 한 키는 이 형식이 전부입니다.

```python
{"t": 0.25, "pose": {"LeftUpLeg": [35.0, 0, 0], "RightLeg": [40.0, 0, 0], ...}}
```

`t`는 0~1로 정규화된 시간. 걷기는 키가 다섯 개뿐입니다 — 접지 / 통과 / 반대
접지 / 반대 통과 / 처음으로(마지막 키는 첫 키와 같아야 이어집니다).

`test3/img2model/animate.py`의 `_swing`이 매개변수 셋에서 모든 본을 계산합니다.

```python
steps = [1.0, 0.0, -1.0, 0.0, 1.0]      # 왼다리 앞 → 통과 → 오른다리 앞 → …
left_leg  =  leg_swing * step
left_arm  = -arm_swing * step            # 팔은 다리와 반대
left_knee =  knee * max(0.0, -step)      # 무릎은 뒤로 간 다리에서만 접힘
LeftFoot  = -left_leg * 0.45             # 발목이 스윙을 상쇄 → 발바닥이 바닥과 나란히
Spine     = [0, -step * 3.0, 0]          # 몸통은 다리와 반대로 비틂(없으면 로봇)
```

`bob`(골반 상하 반동)만 따로 리스트로 붙습니다 — 접지에서 낮고 통과에서 높게,
캐릭터 **키 대비 비율**입니다.

### 캐릭터별 값 — `tools/make_kids.py`의 `KIDS`

| | 클립 | leg_swing | arm_swing | knee | bob |
|---|---|---|---|---|---|
| 도원 (주인공, 0.85m) | Walk | 35 | 21 | 40 | 0.018 |
| | Run | 62 | 40 | 70 | 0.040 |
| | Back | 20 | 12 | 26 | 0.010 |
| | Push | (각도 표를 직접 적음) | | | |
| 적1_박치기 | Walk | 40 | 22 | 44 | 0.016 |
| 적3_던지기 | Walk | 44 | 22 | 46 | 0.016 |
| 선생님 (어른, 1.65m) | Walk | 24 | 24 | 32 | 0.012 |

아이들은 다리가 짧아 성인 기준(24°)으로 흔들면 종종거려 보여서 넓게 잡았습니다.
선생님만 교본 기준값에 가깝습니다.

**보폭을 배속만 보고 키우지 마세요.** 적1_박치기·적3_던지기을 70°까지 넓혔다가 되돌린 적이
있습니다 — 숫자는 좋아졌지만 걷는 게 아니라 성큼 뛰어넘는 자세가 됐습니다.
배속이 좀 높아도 자세가 사람 같은 쪽이 낫고, 배속은 클램프가 받습니다.

## 층 2 — Blender가 키프레임을 찍습니다

`test3/img2model/blender_scripts/walk_worker.py`가 `blender --background`로 돌면서
하는 일은 사실상 두 줄입니다.

```python
pose_bone.rotation_euler = [math.radians(a) for a in angles]
pose_bone.keyframe_insert(data_path="rotation_euler", frame=frame)
```

`frame = 1 + round(t * cycle_frames)`. 키 사이는 Blender의 보간이 채웁니다.

골반 반동만 위치 키인데, **월드의 "위"를 좌표 규약에서 가정하지 않고
`Hips → Head` 방향을 재서** 알아냅니다. 캐릭터 키도 본 위치에서 재서 `bob`
비율에 곱합니다.

액션은 손으로 만들지 않고 `keyframe_insert`가 만들게 둡니다 — Blender 4.4부터
액션이 슬롯 구조로 바뀌어 직접 만들면 버전마다 방법이 달라집니다.

## 층 3 — 굽기 직전에 rogue1이 세 번 손댑니다

`test3`는 다른 프로젝트도 쓰는 공용 코드라, 이 게임에만 필요한 보정은
`tools/make_kids.py`에서 합니다. **순서가 규칙입니다.**

| 순서 | 함수 | 하는 일 | 왜 그 자리인가 |
|---|---|---|---|
| 1 | `fix_knees` | 무릎 각도 부호를 뒤집음 | `_swing`이 양수를 주는데 이 리그는 X+ 가 앞. 그대로 두면 무릎이 반대로 꺾임 |
| 2 | `scale_motion` | 리그 실험실 배율(`assets/anim_tuning.json`)을 각도에 곱함 | 3번보다 **먼저** |
| 3 | `press_arms` | 모든 프레임 어깨 로컬 Z에 상수(−38°)를 더해 A 포즈를 차렷 쪽으로 접음 | 2번에 걸리면 팔이 도로 벌어짐 |

그다음:

- `tools/merge_anims.py`의 `graft`가 캐릭터별 GLB(`_walk` `_run` `_back` `_idle`
  `_push`)를 **이름으로 대응시켜** 한 파일로 합칩니다. Godot이 파일 하나를 씬
  하나로 들여오기 때문입니다.
- `tools/raise_hips.py`가 골반 본을 키의 33%까지 올리고 **inverseBindMatrices를
  다시 계산**합니다. 다시 계산하지 않으면 살가죽이 딸려 올라가 몸이 찌그러집니다.
  `make_kids.py`가 굽기 끝에 자동으로 부릅니다 — **손으로 부르지 마세요.** 여기서
  부르니까 다시 구워도 되돌아가지 않습니다.

측정해 보니 골반이 낮았던 것은 **주인공뿐**이었습니다(23%). 적1_박치기 42%, 적3_던지기 35%,
선생님 49%는 이미 제대로라 도구가 건드리지 않습니다.

## 층 4 — 런타임. 여기가 절반입니다

구운 클립은 다섯 개뿐이고, 화면에 보이는 동작의 절반쯤은 실행 중에 만들어집니다.

### ① 재생 속도가 이동 속도에서 나옵니다 (스케이팅 제거)

`scripts/player.gd`의 `_drive_animation`, `scripts/enemy.gd`의 같은 자리.

```
배속 = 실제 이동 속도 ÷ (그 클립이 1배속에서 바닥을 미는 속도)
```

- **`velocity`가 아니라 `get_real_velocity()`** 를 씁니다. `velocity`는 "가려는"
  속도라 벽에 붙어 밀 때도 남아 제자리 질주가 됩니다.
- 구르는 동안에도 걷기/달리기를 **계속 돌립니다.** 자세 층이 다리를 가리고,
  풀리는 순간 이미 맞는 속도와 위상으로 돌고 있습니다.
- 클램프(주인공 0.35~6.0, 적 0.35~4.0)는 안전장치입니다. 거기 걸리면 그만큼
  미끄러진다는 뜻이고, 제대로 잰 값에서는 안 걸립니다.

**측정 상수 — 클립을 다시 구우면 반드시 다시 재서 옮겨 적어야 합니다.**

| 클립 | 상수 | 값 | 있는 곳 |
|---|---|---|---|
| 주인공 걷기 | `WALK_GROUND` | 0.644 m/s | `player.gd` |
| 주인공 달리기 | `RUN_GROUND` | 1.093 | `player.gd` |
| 주인공 뒷걸음 | `BACK_GROUND` | 0.352 | `player.gd` |
| 적1_박치기 | `WALK_GROUND[FOE_CHARGER]` | 1.141 | `enemy.gd` |
| 적3_던지기 | `[FOE_THROWER]` | 0.994 | `enemy.gd` |
| 선생님 | `[TEACHER]` | 1.304 | `enemy.gd` |
| 아기(베개) | `[BABY]` | 0.531 | `enemy.gd` |
| 여자아이(고함) | `[GIRL]` | 0.613 | `enemy.gd` |
| 남자아이(붙잡기) | `[BOY]` | 0.555 | `enemy.gd` |
| 표에 없는 모델 | `WALK_GROUND_FALLBACK` | 1.100 | `enemy.gd` |

아기·여자아이·남자아이는 원본이 0.72~0.75m 로 작게 나와서, 게임 안에서 다른 아이들과
같은 키(1.25m)로 서도록 `Models.SIZE` 에 배율을 적어 뒀습니다(HERO 와 같은
방법). **미는 속도는 그 배율이 적용된 뒤의 값**이라 표에는 그대로 씁니다 —
`_walk_ground × _scale_now` 로 나누는데 `_scale_now` 에는 그 배율이 없습니다.

`RUN_GROUND`는 문턱도 겸합니다 — "달리기 클립을 1배속으로 돌렸을 때의 속도"를
넘으면 달리기로 바뀝니다. 문턱을 따로 정하지 않으니 클립을 다시 구우면 문턱도
따라옵니다.

> **적의 보폭은 루트가 아니라 `_pivot` 기준으로 재야 합니다.** 적은 자기 노드를
> 돌리지 않고 몸통만 돌립니다. 루트 기준으로 재면 옆으로 걸을 때 앞뒤 성분이
> 사라져 5배 작은 값이 나오고, 다리가 5배 빨리 돕니다.

### ② 뒷걸음질

가는 쪽과 보는 쪽을 내적해서 반대면 **보폭이 좁은 `Back` 클립을 음수 배속**으로
돌립니다. 걷기를 거꾸로 돌리면 보폭이 앞걸음 그대로라 발이 뒤로 성큼 뻗습니다.

문턱 ±0.25 사이에서는 **직전 판단을 유지**합니다. 옆으로 걸을 때 0 근처에서
부호가 떨리면 다리가 앞뒤로 발작합니다.

### ③ 자세 층 — `scripts/pose_override.gd`

클립 위에 **특정 본만** 목표 자세로 당기는 `SkeletonModifier3D`입니다. 값은 각도
규약과 같고, **쉬는 자세 기준의 절대 자세**입니다(클립이 지금 무엇을 하든 같은
모양이 나오도록).

지금 들어 있는 자세:

| 이름 | 언제 | 무엇을 덮는가 |
|---|---|---|
| `ROLL` | 구르는 중 | 온몸 |
| `LUNGE` | 밀기/잡기로 달려드는 중 (`RAM` 에서 섞여 옵니다) | 팔 앞으로 + 몸통 앞으로 |
| `CARRY` | 무언가를 들고 있을 때 | 팔 |
| `SHOUT` | 고함 (0.62초) | 고개 젖힘, 허리 굽힘, 팔 뒤로 |
| `REACH` | 적의 박치기 예고 | 한 손 앞으로 |
| `RAM` | 적의 박치기 돌진 | 머리 숙이고 팔 뒤로 |
| `HURT` | 주인공 피격 | 상체 |
| `HIT` | 적이 고함에 맞음 | 상체 젖힘 |
| `HELD` | 적이 잡혀 있음 | 온몸 |
| `DRINK` | 우유 마시는 중 (0.85초) | 두 손을 얼굴 앞으로, 고개 젖힘 |
| `GUARD` | 베개 아기 — **늘** | 팔 앞으로, 팔꿈치 접음 |
| `SLAM_UP` | 베개 아기 내리치기 예고 | 두 팔 머리 위, 허리 젖힘 |
| `SLAM_DOWN` | 베개 아기 내리친 직후 (0.28초) | 팔 앞아래, 허리 접음 |
| `BLOCK` | **주인공이 막을 때** (0.30초) | 오른 무릎 앞·왼 다리 뒤로 일자, 두 팔로 얼굴 감쌈 |
| `BOUND` | 주인공이 등을 붙잡힘 (최대 1.5초) | 팔 벌려 버둥거림, 허리 접음 |

새로 넣은 넷의 각도는 **이미 재 둔 값을 다시 씁니다.**

| 자세 | 어디서 온 값 |
|---|---|
| `SLAM_UP` 팔 (−100 / 0 / ±34) | `SHOUT` 을 고를 때 잰 표 — 손 높이 0.817m(키 0.85m 이니 머리 위)이고 두 손 간격 0.064m. 고함에서는 그 모이는 것이 문제라 −75 를 골랐지만, 두 손으로 물건 하나를 든 자세에는 그 값이 맞습니다 |
| `SLAM_DOWN` 팔 (74 / 0 / ±24) | `READ` 를 고를 때 잰 값 — 같은 리그에서 "편 팔이 앞아래 45도" |
| `GUARD` 팔 (80 / 0 / ±14, 팔꿈치 38) | `CARRY`(72)보다 조금 더 앞으로, 팔꿈치를 접어 가슴에 안습니다 |
| `BLOCK` 팔 (78 / ±40 / ±84, 팔꿈치 92) | **여기서 새로 쟀습니다** — 아래 표 |
| `BOUND` | `HURT` 의 **반대** — 맞을 때는 팔을 모아 막지만 붙잡혔을 때는 벌려 버둥거려야, 스스로 웅크린 것이 아니라는 것이 읽힙니다 |

### 막기 자세는 재서 골랐습니다 (`--pose=block`)

머리가 큰 아이라 **팔을 앞으로만 올리면 두 손이 얼굴 한가운데에서 겹칩니다.**
처음 값(팔 Y 0)에서는 두 손 사이가 **3.8cm** 였습니다.

| 팔 (X Y Z) | 손 높이 | 머리 한가운데와 | 두 손 사이 |
|---|---|---|---|
| 78 · 0 · 14 | 0.78 | 0.26 | **0.04** ← 겹칩니다 |
| 78 · 26 · 62 | 0.75 | 0.30 | 0.17 |
| **78 · 40 · 84** | **0.80** | **0.25** | **0.23** ← 고른 값 |

**머리뼈가 아니라 머리 한가운데를 기준으로 잽니다.** 뼈는 목 위(0.91)에 있고
머리통은 그보다 위·앞(1.03)으로 큽니다 — 뼈까지의 거리로 재면 얼굴을 뚫고
있어도 「0.2m 떨어짐」으로 읽힙니다.

다리는 오른 무릎이 **0.12m 앞**, 왼발이 **0.16m 뒤**입니다. 그리고 **웅크린
만큼 몸을 내립니다**(`GUARD_CROUCH` 0.09m) — 엉덩이 높이가 고정이라 무릎만
접으면 발이 바닥에서 떠오릅니다(재 봤습니다: 0.03 → 0.11m).

#### 뼈를 재려면 **`skeleton_updated` 를 기다려야 합니다**

자세 층(`SkeletonModifier3D`)은 스켈레톤의 수정 단계에서 도는데, 그것은 게임
코드의 `_process` 보다 **뒤**입니다. 그냥 읽으면 **애니메이션이 써 놓은 값**이
나옵니다.

처음에 그걸 모르고 다리 뼈가 쉼 자세와 한 자리도 안 다르게 나오는 것을 보고
**「자세 층이 다리를 안 쓴다」로 읽었습니다.** `RenderingServer.frame_pre_draw`
로도 안 됩니다. 이 신호라야 수정이 끝난 뒤입니다.

```gdscript
await sk.skeleton_updated
var e := sk.get_bone_pose_rotation(i).get_euler() * 57.2958
```

**베개는 손 본에 매달지 않습니다.** 몸(`_pivot`)의 좌표로 세 자리(가슴 / 머리
위 / 앞아래)를 오갑니다. 손에 붙이면 두 손 사이에 정확히 놓이지만, 그러려면 팔
각도가 바뀔 때마다 베개 크기와 위치를 다시 재야 합니다 — 자세 셋의 손 높이에
맞춘 자리 셋을 오가는 편이 값이 싸고 결과가 같습니다.

**클립을 새로 굽는 대신 이 층을 쓰는 이유:** 고함 자세를 클립으로 구우면 다리까지
덮어써서 고함치는 동안 발이 멈춥니다. 상체 본만 당기면 다리는 걷기 클립이 그대로
돕니다.

**자세끼리 섞으려면 `mix_into` 를 씁니다.** `weight` 는 클립과 자세 사이를 섞는
값이라 자세끼리는 못 섞습니다. `pose` 를 통째로 갈아 끼우면 그 프레임에 각도가
순간이동합니다 - 밀기에서 팔이 뒤(−75°)에서 앞(+84°)으로 159°를 한 프레임에
건너뛰어 "뻗는 동작" 없이 두 장의 그림만 보이던 것이 이것이었습니다. 지금은
남은 거리에서 0~1 을 뽑아(`_lunge_swing`) 둘을 섞습니다 - 거리로 재니 **닿는
순간에 정확히 다 뻗습니다**(실측: 9프레임에 걸쳐 0 → 0.98, 남은거리 0.01).

`_process_modification_with_delta`라는 이름을 씁니다 — 이 엔진 판에서는 델타를
받는 쪽이 불립니다. 잘못 쓰면 **조용히 한 번도 안 불립니다.**

## 리그 실험실 — 제목 화면에서 `R`

`scripts/riglab.gd`. 게임을 켠 채로 리그와 동작을 보고 만지는 화면입니다.

| 손잡이 | 범위 | 무엇을 |
|---|---|---|
| 캐릭터 | 도원 / 적1_박치기 / 적3_던지기 / 선생님 | |
| 동작 | Idle / Walk / Run / Push | |
| 배속 | 0.1 ~ 6배 | |
| 골반 | 18 ~ 50% | **움직이는 그 프레임에** 바뀜 |
| 다리 / 팔 / 상체 / 반동 | 0 ~ 2배 | 프레임마다의 각도에 배율 |
| 프레임 | 세워 놓기 | 크기를 비교하려면 같은 프레임을 봐야 함 |

측정값(골반 %, 1배속 바닥 속도, 손 간격, 팔 길이, 본 개수)을 같이 찍습니다. 바닥
속도는 게임이 스케이팅을 없앨 때 쓰는 것과 **같은 자**라, 여기서 읽은 숫자를
`WALK_GROUND`에 그대로 옮겨 적을 수 있습니다.

**이 화면은 GLB를 고치지 않습니다.** `값 저장` → `assets/anim_tuning.json` →
`make_kids.py`가 구울 때 읽습니다. 파일 하나를 사이에 두는 덕에 미리보기와 굽기가
같은 값을 봅니다. 게임이 에셋을 몰래 고치기 시작하면 무엇이 원본인지 알 수 없게
됩니다.

두 가지 규칙이 걸려 있습니다.

- `riglab.gd`의 `BONE_GROUP`과 `make_kids.py`의 `GROUP_ORDER`는 **같은 표**여야
  합니다. 갈라지면 미리보기와 구운 결과가 달라집니다.
- 저장은 **곱해서 쌓습니다.** 슬라이더는 "지금 클립 대비"라, 한 번 굽고 나면 그
  값이 클립에 들어가 슬라이더는 1.0으로 돌아갑니다.

각도 배율은 축·각도로 풀어서 각도에만 곱합니다(slerp는 사이를 채울 뿐 밖으로
늘리지 못합니다). `q`와 `-q`가 같은 회전이므로 **짧은 쪽으로 돌려놓고** 곱합니다 —
안 하면 20°를 30°로 늘리려다 340°를 510°로 돌립니다.

## 새 동작을 추가하는 법

**세 층 중에 고릅니다. 위로 갈수록 쌉니다.**

### ① 자세 하나면 되는 것 — 몇 분, Blender 불필요

고함·잡기·박치기 예고·피격이 전부 이 방식이었습니다.

1. `pose_override.gd`에 본 각도 표를 `const`로 추가
2. 발동 시점에 `_pose.pose = PoseOverride.<이름>` 하고 `weight`를 올림
3. 부호가 확실하지 않으면 후보 둘을 나란히 렌더해서 고름

**다리가 계속 걸어야 하는 동작이면 반드시 이쪽입니다.**

### ② 다리가 도는 새 사이클이 필요한 것 — Blender 필요

1. `make_kids.py`에 `named_motion("이름", leg_swing=…, …)` 한 줄 (또는 `Push`처럼
   각도 표를 직접 적는 함수)
2. `KIDS`의 해당 캐릭터에 항목 추가, `wanted` 목록에 넣기
3. `python tools/make_kids.py --force --only <캐릭터>`
4. **바닥 미는 속도를 다시 재서** `player.gd` / `enemy.gd` 상수에 옮겨 적기
5. 스케이팅 검사(`--pose=skate`)로 발/몸 비율이 1.0 근처인지 확인

4번을 빼먹으면 스케이팅이 돌아옵니다.

### ③ 크기만 조절 — 리그 실험실

`--ui=riglab`에서 맞추고 `값 저장` → 다시 굽기 → 상수 다시 재기.

## 재는 법

전부 게임 실행 인자입니다. 숫자를 stdout에 찍습니다.

| 인자 | 무엇을 |
|---|---|
| `--pose=stride` | 주인공 걷기 클립이 1배속에서 미는 속도 |
| `--pose=striderun` | 달리기 클립 같은 것 |
| `--pose=stridefoe --foe=<종류>` | 적 클립 같은 것 |

허용 범위: 발/몸 비율 **0.95 ~ 1.05**. 그 밖이면 상수가 틀렸거나 재는 기준
좌표계가 틀린 것입니다(적은 `_pivot` 기준).

### 화면이 정말 나빠졌는지 — 두 장을 빼서 봅니다

메시나 텍스처를 줄일 때 "눈으로 보니 괜찮다"는 못 믿습니다. **씨앗을 고정하고

G=".../Godot_v4.7.1-stable_win64_console.exe"

```python
d = np.abs(np.asarray(A).astype(int) - np.asarray(B).astype(int)).max(axis=2)

**`--seed=` 를 빼먹으면 안 됩니다.** 던전이 매번 달라져서 바닥값이 59% 로

## 알려진 한계

- **발 IK가 없습니다.** 발이 바닥에 닿는 위치를 계산해 다리를 역산하는 층이
  없어서, 경사나 계단에서는 발이 뚫거나 뜹니다. 지금 던전이 평지라 안 드러날
  뿐입니다. 스케이팅도 "발을 붙여서"가 아니라 "평균 속도를 맞춰서" 없앴습니다 —
  통계적으로만 맞고 한 발 한 발이 정확히 붙어 있지는 않습니다.
- **팔이 입에 닿지 않습니다.** 머리가 크고 팔이 짧아 어떻게 접어도 손이 머리뼈
  기준 −0.07m 까지밖에 못 올라갑니다(실측). 우유를 마시는 자세는 **물건 쪽을
  0.15m 올려서**(`DRINK_LIFT`) 그 간격을 메웁니다 - 내려다보는 게임 카메라에서는
  손과 물건 사이가 안 보입니다.
- **좌우가 완벽한 거울이고 사인파입니다.** 체중 이동, 미세한 비대칭, 접지 순간의
  충격이 없습니다. 캡처가 이기는 지점이고 손으로는 못 적습니다.
- **블렌드 트리가 없습니다.** 클립 사이는 `AnimationPlayer.play(clip, 0.12)`의
  단순 교차 페이드입니다.
- 클립을 다시 구우면 **측정 상수가 전부 무효**입니다. 위 표를 다시 채워야 합니다.
